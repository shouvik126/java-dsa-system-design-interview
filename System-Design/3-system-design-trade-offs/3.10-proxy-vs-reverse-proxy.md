# Proxy vs. Reverse Proxy

Both **Forward Proxies (Proxy)** and **Reverse Proxies** act as intermediary servers in computer networks that intercept, manage, and redirect network traffic. However, they differ fundamentally in operational direction, client/server exposure, and intended use cases.

![Proxy vs Reverse Proxy Architecture](https://raw.githubusercontent.com/shouvik126/HLD_images/main/3.10-proxy-vs-reverse-proxy.png)

---

## Proxy (Forward Proxy)

### Operational Direction
A **Forward Proxy** (commonly referred to simply as a *Proxy*) acts on behalf of **clients** (such as web browsers or corporate user devices) seeking resources from external servers across the internet. The client connects directly to the proxy, which then forwards the client's request to the destination server.

```
[ Client A ] ---\
[ Client B ] ----> [ Forward Proxy ] ---> [ Internet / External Web Servers ]
[ Client C ] ---/
```

### Key Functionality
- **Client Privacy & Anonymity**: Masks client identity and IP addresses from destination web servers. The destination server observes the proxy's IP address rather than the client's original IP.
- **Content Filtering & Access Control**: Allows network administrators to enforce security policies, filter content, and block access to unauthorized websites.
- **Caching & Bandwidth Savings**: Caches frequently requested external resources locally, reducing latency and internet bandwidth usage for repetitive requests across a network.

### Real-World Use Case Example: Corporate Network Security
In an enterprise office network, all outbound web requests from employee workstations pass through a forward proxy. The proxy blocks restricted websites, inspects outbound traffic for malware, and caches common web assets to optimize bandwidth.

---

## Reverse Proxy

### Operational Direction
A **Reverse Proxy** acts on behalf of **servers** (such as backend web servers or microservices). Clients (internal or external) connect to the reverse proxy server, which then evaluates and routes incoming requests to appropriate backend application servers.

```
                                          /---> [ Web Server 1 ]
[ External Clients ] ---> [ Reverse Proxy ] ---> [ Web Server 2 ]
                                          \---> [ Web Server 3 ]
```

### Key Functionality
- **Load Balancing**: Distributes incoming client traffic across multiple backend servers to optimize resource utilization and prevent server overload.
- **Server Security & Anonymity**: Hides the internal network topology and IP addresses of backend servers, shielding them from direct public internet exposure and DDoS attacks.
- **SSL/TLS Termination**: Handles CPU-intensive SSL encryption and decryption at the proxy layer, offloading cryptographic overhead from backend application servers.
- **Caching & Compression**: Caches static assets (images, CSS, JS) and compresses HTTP responses (gzip/brotli) to reduce server load and accelerate client page rendering.

### Real-World Use Case Example: High-Traffic Website Architecture
A popular e-commerce platform uses a reverse proxy (e.g., NGINX, HAProxy, Cloudflare) as its public entry point. The reverse proxy terminates HTTPS connections, caches static content, distributes incoming user requests across a pool of backend servers, and protects internal databases from direct internet exposure.

---

## Key Differences

| Feature / Aspect | Forward Proxy | Reverse Proxy |
| :--- | :--- | :--- |
| **Whom It Protects / Represents** | Protects & represents **Clients** (users/browsers). | Protects & represents **Servers** (backend infrastructure). |
| **Traffic Direction** | Manages **outbound** requests to external networks. | Manages **inbound** requests from external clients. |
| **Visibility** | Client is aware of proxy configuration (configured in client browser/OS). | Client is unaware of reverse proxy (interacts as if it were the destination server). |
| **IP Masking** | Hides client IP addresses from destination servers. | Hides backend server IP addresses from external clients. |
| **Core Functions** | Access control, URL filtering, client anonymity, egress caching. | Load balancing, SSL termination, DDoS defense, ingress caching, response compression. |
| **Popular Tools** | Squid, Charles Proxy, Fiddler, Blue Coat. | NGINX, HAProxy, Cloudflare, AWS ALB, Traefik. |

---

## Conclusion

While both Forward Proxies and Reverse Proxies serve as intermediary traffic managers, their operational directions are opposite:
- A **Forward Proxy** is **client-facing**, managing outgoing traffic, user anonymity, and egress internet access.
- A **Reverse Proxy** is **server-facing**, managing incoming traffic, load balancing, security, and ingress performance for backend infrastructure.
