# State Design Pattern

The **State Design Pattern** is a behavioral design pattern that enables an object to alter its behavior when its internal state changes. To client code, the object appears to dynamically change its class at runtime.

![State Design Pattern Overview](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-state-overview.png)

It is particularly valuable in situations where:
- An object exists in one of several distinct states, each governing different operational rules.
- Object methods alter their behavior depending on current state context, which changes over time.
- You want to eliminate large, fragile conditional blocks (`if-else` or `switch`) checking state flags across every method.

Below is a detailed walk-through of how to apply the State Pattern to manage dynamic object behavior in a clean, scalable, and object-oriented structure.

---

## 1. The Problem: Managing Vending Machine States

Imagine building a smart vending machine system. The machine accepts currency, dispenses products, and returns to idle state.

![Vending Machine Problem Scenario](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-vending-machine-problem.png)

The system transitions between distinct operational states:
- **IdleState**: Waiting for user selection (no product chosen, no coins inserted).
- **ItemSelectedState**: Product selected; waiting for payment insertion.
- **HasMoneyState**: Payment inserted; ready to dispense selected product.
- **DispensingState**: Product is actively being dispensed.

The machine exposes user actions:
- `selectItem(String itemCode)`: Select a product to purchase.
- `insertCoin(double amount)`: Insert payment.
- `dispenseItem()`: Trigger product delivery.

Every action must behave differently depending on current machine state. For example, invoking `dispenseItem()` while in `IdleState` should be rejected. Inserting coins before selecting a product should be blocked. Selecting a product during `DispensingState` must be ignored until dispensing completes.

### Naive Implementation: Conditional State Checks

A common naive approach manages state transitions using enum flags and `switch`/`if-else` statements inside a monolithic class:

```java
public class VendingMachineNaive {
    public enum State { IDLE, ITEM_SELECTED, HAS_MONEY, DISPENSING }

    private State currentState = State.IDLE;
    private String selectedItem = null;

    public void selectItem(String itemCode) {
        if (currentState == State.IDLE) {
            this.selectedItem = itemCode;
            this.currentState = State.ITEM_SELECTED;
            System.out.println("Item selected: " + itemCode + ". Insert payment.");
        } else if (currentState == State.ITEM_SELECTED) {
            System.out.println("Item already selected: " + selectedItem);
        } else if (currentState == State.HAS_MONEY) {
            System.out.println("Payment already inserted. Dispense item first.");
        } else if (currentState == State.DISPENSING) {
            System.out.println("Please wait. Dispensing in progress.");
        }
    }

    public void insertCoin(double amount) {
        if (currentState == State.IDLE) {
            System.out.println("Select an item first before inserting payment.");
        } else if (currentState == State.ITEM_SELECTED) {
            this.currentState = State.HAS_MONEY;
            System.out.println("Payment received: $" + amount + ". Ready to dispense.");
        } else if (currentState == State.HAS_MONEY) {
            System.out.println("Payment already provided.");
        } else if (currentState == State.DISPENSING) {
            System.out.println("Cannot insert coins while dispensing.");
        }
    }

    public void dispenseItem() {
        if (currentState == State.HAS_MONEY) {
            this.currentState = State.DISPENSING;
            System.out.println("Dispensing product: " + selectedItem);
            this.selectedItem = null;
            this.currentState = State.IDLE;
            System.out.println("Transaction complete. Returning to Idle state.");
        } else {
            System.out.println("Cannot dispense item in current state: " + currentState);
        }
    }
}
```

### Why This Approach Fails at Scale

1. **Monolithic Code Duplication**  
   Every user method (`selectItem`, `insertCoin`, `dispenseItem`) contains duplicated conditional structures evaluating `currentState`.

2. **Violation of Open/Closed Principle**  
   Introducing new states (e.g., `OutOfStockState` or `MaintenanceState`) requires updating every conditional block in every method across the entire class.

3. **Violation of Single Responsibility Principle**  
   `VendingMachineNaive` handles state tracking, transition validation, business rules, and hardware execution in one bloated class.

### Desired Architecture
We require a design that:
- Encapsulates state-specific rules into dedicated state classes.
- Delegates action handling to the active state object.
- Enables new states to be added without modifying existing state classes or context code.

This is the exact goal of the **State Design Pattern**.

## 2. The State Design Pattern

The State Pattern delegates behavior to state objects representing current context status.

Core principles:
- **State Encapsulation**: State-specific behavior and transition logic live entirely inside concrete state classes.
- **State-Driven Transitions**: State objects trigger transitions by setting a new state on the context object.

### Real-World Analogy

Consider a traffic light controller. The light transitions between Red, Yellow, and Green states. 
- **Red State**: Stop traffic, timer counts down, transitions to Green.
- **Green State**: Allow traffic, timer counts down, transitions to Yellow.
- **Yellow State**: Warn traffic, timer counts down, transitions to Red.

The traffic light hardware (Context) delegates behavior to its active state object. Each state manages its own operational rules and transition triggers.

### Class Diagram

![State Class Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-state-class-diagram.png)

### Pattern Participants

1. **State Interface (`MachineState`)**  
   Declares action method contracts supported by the context.

2. **Concrete States (`IdleState`, `ItemSelectedState`, `HasMoneyState`, `DispensingState`)**  
   Implements state-specific handling rules and manages transitions.

3. **Context (`VendingMachine`)**  
   Maintains a reference to the active `MachineState` instance and delegates incoming requests to it.

---

## 3. How It Works

The workflow execution of the State pattern follows this delegation cycle:

![State Execution Workflow](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-state-workflow.png)

1. **Context Initialization**: `VendingMachine` initializes with `IdleState`.
2. **Client Invokes Request**: Client calls `machine.selectItem("A1")`.
3. **Delegation**: `VendingMachine` delegates to `currentState.selectItem(this, "A1")`.
4. **Logic & State Transition**: `IdleState` validates the request and transitions context state via `context.setState(new ItemSelectedState())`.
5. **Subsequent Actions**: Future requests dispatch to the new `ItemSelectedState` object.

## 4. Implementing the State Pattern

Refactoring the vending machine using the State Pattern decouples state rules and transition logic.

![State Transition Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-state-transition-diagram.png)

### Step 1: Define the State Interface

```java
public interface MachineState {
    void selectItem(VendingMachine machine, String itemCode);
    void insertCoin(VendingMachine machine, double amount);
    void dispenseItem(VendingMachine machine);
}
```

### Step 2: Implement Concrete State Classes

#### Idle State
```java
public class IdleState implements MachineState {
    @Override
    public void selectItem(VendingMachine machine, String itemCode) {
        System.out.println("Item '" + itemCode + "' selected.");
        machine.setSelectedItem(itemCode);
        machine.setState(new ItemSelectedState());
    }

    @Override
    public void insertCoin(VendingMachine machine, double amount) {
        System.out.println("Please select an item first before inserting payment.");
    }

    @Override
    public void dispenseItem(VendingMachine machine) {
        System.out.println("Cannot dispense. No item selected or paid for.");
    }
}
```

#### Item Selected State
```java
public class ItemSelectedState implements MachineState {
    @Override
    public void selectItem(VendingMachine machine, String itemCode) {
        System.out.println("Item already selected: " + machine.getSelectedItem() + ". Proceed to payment.");
    }

    @Override
    public void insertCoin(VendingMachine machine, double amount) {
        System.out.println("Payment of $" + amount + " accepted for " + machine.getSelectedItem());
        machine.setState(new HasMoneyState());
    }

    @Override
    public void dispenseItem(VendingMachine machine) {
        System.out.println("Payment required before dispensing.");
    }
}
```

#### Has Money State
```java
public class HasMoneyState implements MachineState {
    @Override
    public void selectItem(VendingMachine machine, String itemCode) {
        System.out.println("Payment already inserted. Dispense current item first.");
    }

    @Override
    public void insertCoin(VendingMachine machine, double amount) {
        System.out.println("Full payment already accepted.");
    }

    @Override
    public void dispenseItem(VendingMachine machine) {
        System.out.println("Dispensing item...");
        machine.setState(new DispensingState());
        machine.getcurrentState().dispenseItem(machine); // Trigger automated release
    }
}
```

#### Dispensing State
```java
public class DispensingState implements MachineState {
    @Override
    public void selectItem(VendingMachine machine, String itemCode) {
        System.out.println("Please wait. Currently dispensing.");
    }

    @Override
    public void insertCoin(VendingMachine machine, double amount) {
        System.out.println("Please wait. Currently dispensing.");
    }

    @Override
    public void dispenseItem(VendingMachine machine) {
        System.out.println("Product '" + machine.getSelectedItem() + "' released to tray.");
        machine.setSelectedItem(null);
        machine.setState(new IdleState());
        System.out.println("Machine returned to Idle state.\n");
    }
}
```

### Step 3: Implement Context Class (`VendingMachine`)

```java
public class VendingMachine {
    private MachineState currentState;
    private String selectedItem;

    public VendingMachine() {
        this.currentState = new IdleState(); // Initial state
    }

    public void setState(MachineState state) {
        this.currentState = state;
    }

    public MachineState getcurrentState() {
        return currentState;
    }

    public String getSelectedItem() {
        return selectedItem;
    }

    public void setSelectedItem(String itemCode) {
        this.selectedItem = itemCode;
    }

    // Context methods delegating to current state
    public void selectItem(String itemCode) {
        currentState.selectItem(this, itemCode);
    }

    public void insertCoin(double amount) {
        currentState.insertCoin(this, amount);
    }

    public void dispenseItem() {
        currentState.dispenseItem(this);
    }
}
```

### Step 4: Client Execution & Verification

```java
public class StatePatternDemo {
    public static void main(String[] args) {
        VendingMachine machine = new VendingMachine();

        System.out.println("--- Successful Purchase Transaction ---");
        machine.selectItem("A1");
        machine.insertCoin(1.75);
        machine.dispenseItem();

        System.out.println("--- Invalid Action Sequence Test ---");
        machine.insertCoin(2.00); // Invalid: No item selected
        machine.dispenseItem();   // Invalid: No item selected
        
        machine.selectItem("B2");
        machine.insertCoin(1.50);
        machine.dispenseItem();
    }
}
```

### Console Output
```text

Dispensing item...
Product 'A1' released to tray.
Machine returned to Idle state.

```

## 5. Practical Example: Document Workflow Management

Consider a content publishing system where documents transition across workflow states: `Draft`, `Under Review`, and `Published`.

![Document Workflow Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.36-document-workflow-diagram.png)

### Implementation

```java
// State Interface
public interface DocumentState {
    void edit(DocumentContext doc, String text);
    void submitForReview(DocumentContext doc);
    void approve(DocumentContext doc);
    void reject(DocumentContext doc);
    void unpublish(DocumentContext doc);
}

// Context
public class DocumentContext {
    private DocumentState state;
    private String content = "";

    public DocumentContext() {
        this.state = new DraftState();
    }

    public void setState(DocumentState state) {
        this.state = state;
    }

    public DocumentState getState() { return state; }
    public String getContent() { return content; }
    public void setContent(String content) { this.content = content; }

    public void edit(String text) { state.edit(this, text); }
    public void submitForReview() { state.submitForReview(this); }
    public void approve() { state.approve(this); }
    public void reject() { state.reject(this); }
    public void unpublish() { state.unpublish(this); }
}

// Concrete State 1: Draft
public class DraftState implements DocumentState {
    @Override
    public void edit(DocumentContext doc, String text) {
        doc.setContent(text);
        System.out.println("Draft updated: \"" + text + "\"");
    }

    @Override
    public void submitForReview(DocumentContext doc) {
        System.out.println("Document submitted for review.");
        doc.setState(new ReviewState());
    }

    @Override
    public void approve(DocumentContext doc) { System.out.println("Draft cannot be approved directly."); }

    @Override
    public void reject(DocumentContext doc) { System.out.println("Draft cannot be rejected."); }

    @Override
    public void unpublish(DocumentContext doc) { System.out.println("Draft is not published."); }
}

// Concrete State 2: Under Review
public class ReviewState implements DocumentState {
    @Override
    public void edit(DocumentContext doc, String text) {
        System.out.println("Cannot edit document while under review.");
    }

    @Override
    public void submitForReview(DocumentContext doc) {
        System.out.println("Document is already under review.");
    }

    @Override
    public void approve(DocumentContext doc) {
        System.out.println("Document approved! Published live.");
        doc.setState(new PublishedState());
    }

    @Override
    public void reject(DocumentContext doc) {
        System.out.println("Document rejected. Returning to draft.");
        doc.setState(new DraftState());
    }

    @Override
    public void unpublish(DocumentContext doc) { System.out.println("Document is not published yet."); }
}

// Concrete State 3: Published
public class PublishedState implements DocumentState {
    @Override
    public void edit(DocumentContext doc, String text) {
        System.out.println("Published document is read-only. Unpublish to edit.");
    }

    @Override
    public void submitForReview(DocumentContext doc) { System.out.println("Already published."); }

    @Override
    public void approve(DocumentContext doc) { System.out.println("Already published."); }

    @Override
    public void reject(DocumentContext doc) { System.out.println("Cannot reject published document."); }

    @Override
    public void unpublish(DocumentContext doc) {
        System.out.println("Document unpublished. Returned to draft state.");
        doc.setState(new DraftState());
    }
}
```

```java
// Client Demo
public class DocumentWorkflowDemo {
    public static void main(String[] args) {
        DocumentContext doc = new DocumentContext();

        doc.edit("Low-Level Design Guide v1.0");
        doc.submitForReview();

        // Attempt invalid edit during review
        doc.edit("Attempting unauthorized edit...");

        // Approve document
        doc.approve();

        // Attempt edit on published document
        doc.edit("Modifying published content");

        // Unpublish back to draft
        doc.unpublish();
        doc.edit("Low-Level Design Guide v1.1 (Revised)");
    }
}
```

### Console Output
```text
Draft updated: "Low-Level Design Guide v1.0"
Document submitted for review.
Cannot edit document while under review.
Document approved! Published live.
Published document is read-only. Unpublish to edit.
Document unpublished. Returned to draft state.
Draft updated: "Low-Level Design Guide v1.1 (Revised)"
```

### Summary
`DocumentContext` maintains zero conditional logic checking state flags. State transitions and operational constraints are fully encapsulated within `DraftState`, `ReviewState`, and `PublishedState`. Adding a new workflow state (such as `ArchivedState`) requires creating one class without editing existing state implementations.
