# Template Method Design Pattern

The **Template Method Design Pattern** is a behavioral design pattern that defines the skeleton of an algorithm in an abstract base class, allowing subclasses to override specific steps without modifying the algorithm's overall structural flow.

![Template Method Design Pattern Overview](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.38-template-method-overview.png)

It is particularly valuable in situations where:
- You have a well-defined sequence of steps required to execute a workflow.
- Invariant parts of an algorithm are shared across all implementations.
- Variant parts should be customized by subclasses without compromising step execution order.

Below is a detailed walk-through of how to apply the Template Method Pattern to build reusable, extensible, and consistent workflow pipelines.

---

## 1. The Problem: Exporting Analytics Reports

Imagine building an analytics platform that exports data reports in CSV and PDF formats, with Excel support planned for a future release.

Every report exporter follows an identical high-level workflow:
1. **Prepare Data**: Gather and structure data from the database.
2. **Open File**: Initialize the destination output file.
3. **Write Header**: Output format-specific column headers or metadata.
4. **Write Data Rows**: Iterate over records and format data rows.
5. **Write Footer**: Add optional summary or page footer metadata.
6. **Close File**: Finalize and flush the output file stream.

While the high-level workflow is identical across formats, header formatting and row rendering differ per format.

### Naive Implementation: Independent Exporters

When each exporter implements the complete workflow independently, logic duplication occurs:

```java
import java.util.Arrays;
import java.util.List;

public class ReportData {
    public List<String> getHeaders() {
        return Arrays.asList("ID", "User", "Amount");
    }

    public List<List<String>> getRows() {
        return Arrays.asList(
            Arrays.asList("101", "Alice", "$150.00"),
            Arrays.asList("102", "Bob", "$220.50")
        );
    }
}
```

```java
public class CsvReportExporterNaive {
    public void exportReport(ReportData data, String path) {
        System.out.println("Preparing data for CSV export...");
        System.out.println("Opening CSV file stream at: " + path);

        // CSV-specific header
        System.out.println("Writing CSV Header: " + String.join(",", data.getHeaders()));

        // CSV-specific data rows
        for (List<String> row : data.getRows()) {
            System.out.println("Writing CSV Row: " + String.join(",", row));
        }

        System.out.println("Closing CSV file stream.");
        System.out.println("CSV export completed successfully.\n");
    }
}
```

```java
public class PdfReportExporterNaive {
    public void exportReport(ReportData data, String path) {
        System.out.println("Preparing data for PDF export...");
        System.out.println("Opening PDF graphics canvas at: " + path);

        // PDF-specific header
        System.out.println("Rendering PDF Title Banner & Headers: " + data.getHeaders());

        // PDF-specific data rows
        for (List<String> row : data.getRows()) {
            System.out.println("Rendering PDF Table Cell Box: " + row);
        }

        // PDF-specific footer
        System.out.println("Rendering PDF Page Footer: Page 1 of 1");

        System.out.println("Closing PDF document writer.");
        System.out.println("PDF export completed successfully.\n");
    }
}
```

```java

    public static void main(String[] args) {
        ReportData data = new ReportData();
        CsvReportExporterNaive csvExporter = new CsvReportExporterNaive();
        PdfReportExporterNaive pdfExporter = new PdfReportExporterNaive();

        csvExporter.exportReport(data, "sales_report.csv");
        pdfExporter.exportReport(data, "sales_report.pdf");
    }
}
```

### Why This Design Fails as the System Grows

1. **Code Duplication**  
   Common tasks—data preparation, file initialization, and stream closing—are duplicated in every exporter class.

2. **Maintenance Overhead**  
   Adding logging, error handling, or buffering requires editing every exporter class. Missing one exporter introduces subtle operational discrepancies.

3. **Workflow Drift & Inconsistency**  
   Nothing prevents a developer from accidentally reordering execution steps or omitting cleanup calls in a new exporter subclass.

4. **Violates DRY (Don't Repeat Yourself)**  
   Creating a new format requires copying boilerplate and editing only a few formatting lines.

### Desired Architecture
We require a design that:
- Defines the common report export workflow once in an abstract base class.
- Forces template step execution order via a `final` template method.
- Allows subclasses to customize format-specific steps (`writeHeader`, `writeDataRows`) and optional hooks (`writeFooter`).

This is precisely what the **Template Method Design Pattern** achieves.

## 2. The Template Method Pattern

The Template Method pattern defines the skeleton of an algorithm inside a base class method, delegating specific steps to concrete subclasses.

Core characteristics:
- **Algorithm Skeleton in Base Class**: The base class defines the fixed step sequence inside a `final` template method.
- **Subclass-Driven Step Overrides**: Subclasses implement abstract methods for variable steps, but never alter execution ordering.

### Real-World Analogy

Consider a standard cake recipe template:
1. Preheat oven (common step).
2. Prepare batter (variable step: chocolate, vanilla, or carrot).
3. Pour batter into pan (common step).
4. Bake for specified duration (common step).
5. Frost cake (optional hook step).

The step sequence is locked by the general recipe. Subclasses customize only the batter composition and optional frosting additions.

### Class Diagram

![Template Method Class Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.38-template-method-class-diagram.png)

### Pattern Participants

1. **AbstractClass (`AbstractReportExporter`)**  
   Contains the `final` template method defining the step sequence, implements default shared logic, declares abstract step methods, and provides default hook implementations.

2. **ConcreteClasses (`CsvReportExporter`, `PdfReportExporter`, `ExcelReportExporter`)**  
   Extends the abstract class and implements format-specific abstract methods and optional hooks.

## 3. How It Works

The workflow execution follows a structured template sequence:

![Template Method Execution Workflow](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.38-template-method-workflow.png)

1. **Client Invocation**: Client calls `exporter.exportReport(data, path)` on a concrete instance.
2. **Template Execution**: The `final exportReport` method in `AbstractReportExporter` starts executing.
3. **Shared Base Steps**: Invariant methods (`prepareData`, `openFile`, `closeFile`) run base class logic.
4. **Subclass Step Dispatch**: Variable steps (`writeHeader`, `writeDataRows`) dispatch to the concrete subclass.
5. **Hook Execution**: `writeFooter()` executes default base logic unless overridden by the subclass.

## 4. Implementing the Template Method Pattern

Let's refactor the report exporter framework using the Template Method pattern.

### Step 1: Create the Abstract Base Class

```java
public abstract class AbstractReportExporter {

    // Template Method (final prevents subclasses from altering step order)
    public final void exportReport(ReportData data, String path) {
        prepareData(data);
        openFile(path);
        writeHeader(data);       // Abstract step
        writeDataRows(data);     // Abstract step
        writeFooter(data);       // Hook method (optional override)
        closeFile(path);
        System.out.println("Export completed successfully for: " + path + "\n");
    }

    // Invariant Steps (shared base logic)
    protected void prepareData(ReportData data) {
        System.out.println("Preparing report data records...");
    }

    protected void openFile(String path) {
        System.out.println("Opening target output file at: " + path);
    }

    protected void closeFile(String path) {
        System.out.println("Flushing buffers and closing file stream.");
    }

    // Primitive Methods (must be implemented by subclasses)
    protected abstract void writeHeader(ReportData data);
    protected abstract void writeDataRows(ReportData data);

    // Hook Method (default empty implementation; opt-in for subclasses)
    protected void writeFooter(ReportData data) {
        // Default: No footer
    }
}
```

### Step 2: Implement Concrete Exporters

#### CSV Exporter
```java
import java.util.List;

public class CsvReportExporter extends AbstractReportExporter {

    @Override
    protected void writeHeader(ReportData data) {
        System.out.println("CSV Header: " + String.join(",", data.getHeaders()));
    }

    @Override
    protected void writeDataRows(ReportData data) {
        for (List<String> row : data.getRows()) {
            System.out.println("CSV Row: " + String.join(",", row));
        }
    }
    // Uses default empty writeFooter hook
}
```

#### PDF Exporter

## 5. Evolving the System: Adding an Excel Exporter

When requirements demand an Excel exporter, we create a single new subclass without modifying existing code:

```java
import java.util.List;

public class ExcelReportExporter extends AbstractReportExporter {

    @Override
    protected void writeHeader(ReportData data) {
        System.out.println("Excel Worksheet Header Row: " + data.getHeaders());
    }

    @Override
    protected void writeDataRows(ReportData data) {
        for (List<String> row : data.getRows()) {
            System.out.println("Excel Cell Values: " + row);
        }
    }

    @Override
    protected void writeFooter(ReportData data) {
        System.out.println("Excel Formula Summary Row: SUM(C2:C3)");
    }
}
```

Adding `ExcelReportExporter` adheres to the **Open/Closed Principle**: open for extension (new exporter subclass), closed for modification (`AbstractReportExporter` remains untouched).

## 6. Practical Example: E-Commerce Order Processing Pipeline

Consider an e-commerce platform where orders go through a processing pipeline: validate order, calculate total, apply discount, process payment, and send confirmation.

![Order Processing Class Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.38-order-processing-class-diagram.png)

### Implementation

```java
// Order Model
public class Order {
    private final String orderId;
    private final double amount;
    private final String customerType;

    public Order(String orderId, double amount, String customerType) {
        this.orderId = orderId;
        this.amount = amount;
        this.customerType = customerType;
    }

    public String getOrderId() { return orderId; }
    public double getAmount() { return amount; }
    public String getCustomerType() { return customerType; }
}

// Abstract Template Processor
public abstract class OrderProcessor {

    // Template Method
    public final void processOrder(Order order) {
        validateOrder(order);
        double total = calculateTotal(order);
        double discountedTotal = applyDiscount(order, total); // Hook method
        processPayment(order, discountedTotal);
        sendConfirmation(order);                             // Hook method
        System.out.println("Order [" + order.getOrderId() + "] processed successfully.\n");
    }

    protected void validateOrder(Order order) {
        System.out.println("Validating items and stock for Order #" + order.getOrderId());
    }

    protected abstract double calculateTotal(Order order);
    protected abstract void processPayment(Order order, double finalAmount);

    // Optional Hook: Default returns original total
    protected double applyDiscount(Order order, double total) {
        return total;
    }

    // Optional Hook: Default standard email confirmation
    protected void sendConfirmation(Order order) {
        System.out.println("Sending standard email confirmation for Order #" + order.getOrderId());
    }
}

// Concrete Processor 1: Standard Order
public class StandardOrderProcessor extends OrderProcessor {
    @Override
    protected double calculateTotal(Order order) {
        double shipping = 10.0;
        System.out.println("Standard Order Total: $" + order.getAmount() + " + $" + shipping + " shipping.");
        return order.getAmount() + shipping;
    }

    @Override
    protected void processPayment(Order order, double finalAmount) {
        System.out.println("Processing credit card payment of $" + finalAmount);
    }
}

// Concrete Processor 2: Prime Priority Order
public class PrimeOrderProcessor extends OrderProcessor {
    @Override
    protected double calculateTotal(Order order) {
        System.out.println("Prime Order Total: $" + order.getAmount() + " (Free Shipping).");
        return order.getAmount();
    }

    @Override
    protected double applyDiscount(Order order, double total) {
        double discount = total * 0.10; // 10% Prime member discount
        System.out.println("Applied 10% Prime Discount: -$" + discount);
        return total - discount;
    }

    @Override
    protected void processPayment(Order order, double finalAmount) {
        System.out.println("Processing 1-Click Prime payment of $" + finalAmount);
    }
}

// Concrete Processor 3: International Order
public class InternationalOrderProcessor extends OrderProcessor {
    @Override
    protected double calculateTotal(Order order) {
        double customsFee = 25.0;
        System.out.println("International Order Total: $" + order.getAmount() + " + $" + customsFee + " customs duty.");
        return order.getAmount() + customsFee;
    }

    @Override
    protected void processPayment(Order order, double finalAmount) {
        System.out.println("Processing multi-currency international wire transfer of $" + finalAmount);
    }

    @Override
    protected void sendConfirmation(Order order) {
        System.out.println("Sending multilingual notification & customs tracking link for Order #" + order.getOrderId());
    }
}
```

```java
// Client Demo
public class OrderProcessorDemo {
    public static void main(String[] args) {
        Order standardOrder = new Order("ORD-101", 100.0, "Standard");
        Order primeOrder = new Order("ORD-102", 200.0, "Prime");
        Order intlOrder = new Order("ORD-103", 300.0, "International");

        OrderProcessor standardProcessor = new StandardOrderProcessor();
        OrderProcessor primeProcessor = new PrimeOrderProcessor();
        OrderProcessor intlProcessor = new InternationalOrderProcessor();

        System.out.println("--- Processing Standard Order ---");
        standardProcessor.processOrder(standardOrder);

        System.out.println("--- Processing Prime Order ---");
        primeProcessor.processOrder(primeOrder);

        System.out.println("--- Processing International Order ---");
        intlProcessor.processOrder(intlOrder);
    }
}
```

### Summary
The base `OrderProcessor` locks the execution sequence. `StandardOrderProcessor`, `PrimeOrderProcessor`, and `InternationalOrderProcessor` customize steps (`calculateTotal`, `processPayment`) and selectively override hooks (`applyDiscount`, `sendConfirmation`) without changing the overall order processing flow.
