# Facade Design Pattern

The **Facade Design Pattern** is a structural design pattern that provides a simplified, unified interface to a complex subsystem. Rather than requiring clients to orchestrate numerous low-level components directly, a facade encapsulates internal complexity and exposes a clean, single entry point.

![Facade Design Pattern Overview](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-facade-overview.png)

It is particularly valuable in situations where:
- Your application integrates multiple interdependent classes or low-level APIs.
- Client applications do not need exposure to internal subsystem workflows.
- You want to reduce coupling and simplify system accessibility.

In real-world applications, completing a routine business operation frequently requires coordinating multiple components. Without a facade, every client must communicate with several subsystems independently and manage operation sequences manually.

### Architecture Without Facade
![Architecture Without Facade](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-without-facade.png)

### Architecture With Facade
![Architecture With Facade](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-with-facade.png)

By introducing a facade, client code interacts with a single object while the facade coordinates subsystem invocations behind the scenes. This minimizes client complexity, eliminates tight coupling, and enhances maintainability.

## 1. The Problem: Deployment Automation Complexity

Consider building a deployment automation tool for software engineering teams.

While deploying an application appears straightforward, it requires a sequence of tightly coordinated steps:
1. Pulling the latest source code from a version control repository.
2. Compiling the application and packaging a build artifact.
3. Executing automated test suites (unit, integration, and security scans).
4. Delivering and activating the build artifact on a target server.

Each step is managed by a distinct subsystem class with its own specialized API.

### Deployment Subsystems

#### 1. Version Control System (VCS)
```java
public class VersionControlSystem {
    public void pullLatestChanges(String branch) {
        System.out.println("VCS: Pulling latest changes from branch '" + branch + "'...");
    }
}
```

#### 2. Build System
```java
public class BuildSystem {
    public boolean compileProject() {
        System.out.println("BuildSystem: Compiling source code...");
        return true;
    }

    public String getArtifactPath() {
        return "target/app-v1.0.jar";
    }
}
```

#### 3. Testing Framework
```java
public class TestingFramework {
    public boolean runUnitTests() {
        System.out.println("TestingFramework: Running unit tests...");
        return true;
    }

    public boolean runIntegrationTests() {
        System.out.println("TestingFramework: Running integration tests...");
        return true;
    }
}
```

#### 4. Deployment Target
```java
public class DeploymentTarget {
    public void transferArtifact(String artifactPath, String server) {
        System.out.println("DeploymentTarget: Transferring artifact '" + artifactPath + 
                           "' to server '" + server + "'...");
    }

    public void activateNewVersion(String server) {
        System.out.println("DeploymentTarget: Activating new deployment version on '" + server + "'...");
    }
}
```

### Client Code Without Facade

Without a facade, client code must interact directly with all four subsystems, managing call order and error states explicitly.

![Client Subsystem Interaction Without Facade](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-client-subsystem-sequence.png)

```java
public class NaiveDeploymentClient {
    public static void main(String[] args) {
        String branch = "main";
        String server = "prod-server-01.company.com";

        VersionControlSystem vcs = new VersionControlSystem();
        BuildSystem buildSystem = new BuildSystem();
        TestingFramework testingFramework = new TestingFramework();
        DeploymentTarget deploymentTarget = new DeploymentTarget();

        // Manual orchestration across subsystems
        vcs.pullLatestChanges(branch);
        
        if (buildSystem.compileProject()) {
            String artifact = buildSystem.getArtifactPath();
            
            if (testingFramework.runUnitTests() && testingFramework.runIntegrationTests()) {
                deploymentTarget.transferArtifact(artifact, server);
                deploymentTarget.activateNewVersion(server);
                System.out.println("Deployment completed successfully!");
            } else {
                System.out.println("Deployment aborted: Test failures detected.");
            }
        } else {
            System.out.println("Deployment aborted: Build compilation failed.");
        }
    }
}
```

### Flaws in This Design
1. **High Client Complexity**: Client code must understand every subsystem API, required parameters, execution sequences, and failure recovery.
2. **Tight Coupling**: Clients depend directly on `VersionControlSystem`, `BuildSystem`, `TestingFramework`, and `DeploymentTarget`. Modifying any subsystem method signature forces changes across all client call sites.
3. **Duplicated Orchestration Logic**: Reusing deployment logic across webhooks, scheduled jobs, or CLI tools duplicates sequence handling and error recovery code.
4. **Fragile Testing**: Unit testing client code requires mocking all underlying subsystem dependencies.

## 2. The Facade Design Pattern

The Facade pattern introduces a higher-level interface that encapsulates subsystem complexities and exposes only essential operations to clients.

### Real-World Analogy: Hotel Concierge
Guests at a hotel do not directly contact housekeeping for towels, kitchen staff for dinner reservations, and valet attendants for vehicles. Instead, they make a single request to the **Concierge Desk** (the Facade). The concierge coordinates internal departments (the Subsystems) to fulfill the request, insulating guests from internal hotel operations.

![Facade Pattern Class Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-facade-class-diagram.png)
### Participants in the Pattern
- **Facade** (`DeploymentFacade`): Coordinates subsystem classes and exposes simplified entry points.
- **Subsystem Classes** (`VersionControlSystem`, `BuildSystem`, etc.): Implement low-level domain operations. Subsystems remain unaware of the facade and can still be used independently.
- **Client**: Interacts exclusively with the Facade to execute high-level workflows.

### The Facade Implementation

```java
public class DeploymentFacade {
    private final VersionControlSystem vcs;
    private final BuildSystem buildSystem;
    private final TestingFramework testingFramework;
    private final DeploymentTarget deploymentTarget;

    public DeploymentFacade() {
        this.vcs = new VersionControlSystem();
        this.buildSystem = new BuildSystem();
        this.testingFramework = new TestingFramework();
        this.deploymentTarget = new DeploymentTarget();
    }

    // High-level method hiding internal subsystem orchestration
    public boolean deployApplication(String branch, String server) {
        System.out.println("\n--- Starting Deployment Pipeline for Branch: " + branch + " ---");
        
        vcs.pullLatestChanges(branch);

        if (!buildSystem.compileProject()) {
            System.err.println("Deployment failed: Build step unsuccessful.");
            return false;
        }

        String artifactPath = buildSystem.getArtifactPath();

        if (!testingFramework.runUnitTests() || !testingFramework.runIntegrationTests()) {
            System.err.println("Deployment failed: Automated test suite failed.");
            return false;
        }

        deploymentTarget.transferArtifact(artifactPath, server);
        deploymentTarget.activateNewVersion(server);

        System.out.println("--- Deployment Successfully Completed on " + server + " ---");
        return true;
    }
}
```

### Simplified Client Execution

![Client Interacting with Deployment Facade](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-client-facade-interaction.png)

```java
public class FacadeDeploymentClient {
    public static void main(String[] args) {
        DeploymentFacade deploymentFacade = new DeploymentFacade();

        // Client makes a single call without handling subsystem orchestration
        boolean prodSuccess = deploymentFacade.deployApplication("main", "prod-server-01.company.com");
        boolean stagingSuccess = deploymentFacade.deployApplication("feature/ui", "staging-server.company.com");

        System.out.println("Production deployment status: " + prodSuccess);
        System.out.println("Staging deployment status: " + stagingSuccess);
    }
}
```

```text
DeploymentTarget: Activating new deployment version on 'prod-server-01.company.com'...

```

## Evolution Without Breaking Client Code

The Facade pattern decouples clients from internal subsystem updates. Supposing new requirements emerge—such as adding security scans (`SecurityScanner`) or sending Slack notifications (`NotificationService`) post-deployment:

```java
public class EvolvedDeploymentFacade {
    private final DeploymentFacade baseFacade;
    // New internal subsystems can be integrated seamlessly

    public EvolvedDeploymentFacade() {
        this.baseFacade = new DeploymentFacade();
    }

    public boolean deployApplication(String branch, String server) {
        return baseFacade.deployApplication(branch, server);
    }

    // Additional convenience methods added without breaking existing callers
    public boolean deployHotfix(String branch, String server) {
        System.out.println("Executing expedited hotfix deployment...");
        return baseFacade.deployApplication(branch, server);
    }
}
```

Existing clients continue invoking `deployApplication()` without modification, while new capabilities are integrated within the facade layer.

## 4. Practical Real-World Example: Home Theater System

Consider a home theater setup consisting of an Amplifier, DVD Player, Projector, Smart Lights, and Streaming Service. Watching a movie requires powering on devices, configuring inputs, setting volume levels, and dimming lights in sequence.

![Home Theater Facade Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.15-home-theater-facade.png)

### Home Theater Subsystems & Facade Implementation

```java
class Amplifier {
    public void on() { System.out.println("Amplifier turned ON"); }
    public void setSurroundSound() { System.out.println("Amplifier set to 5.1 Surround Sound"); }
    public void setVolume(int level) { System.out.println("Amplifier volume set to " + level); }
    public void off() { System.out.println("Amplifier turned OFF"); }
}

class Projector {
    public void on() { System.out.println("Projector turned ON"); }
    public void setWideScreenMode() { System.out.println("Projector set to 16:9 Widescreen Mode"); }
    public void off() { System.out.println("Projector turned OFF"); }
}

class SmartLights {
    public void dim(int percentage) { System.out.println("Smart Lights dimmed to " + percentage + "%"); }
    public void on() { System.out.println("Smart Lights turned ON full brightness"); }
}

class DvdPlayer {
    public void on() { System.out.println("DVD Player turned ON"); }
    public void play(String movie) { System.out.println("Playing movie: '" + movie + "'"); }
    public void stop() { System.out.println("DVD Player stopped"); }
    public void off() { System.out.println("DVD Player turned OFF"); }
}

// Facade Class
public class HomeTheaterFacade {
    private final Amplifier amp;
    private final Projector projector;
    private final SmartLights lights;
    private final DvdPlayer dvd;

    public HomeTheaterFacade(Amplifier amp, Projector projector, SmartLights lights, DvdPlayer dvd) {
        this.amp = amp;
        this.projector = projector;
        this.lights = lights;
        this.dvd = dvd;
    }

    public void watchMovie(String movie) {
        System.out.println("\n--- Preparing Home Theater for Movie ---");
        lights.dim(10);
        projector.on();
        projector.setWideScreenMode();
        amp.on();
        amp.setSurroundSound();
        amp.setVolume(7);
        dvd.on();
        dvd.play(movie);
        System.out.println("--- Movie Playing Enjoy! ---");
    }

    public void endMovie() {
        System.out.println("\n--- Shutting Down Home Theater ---");
        dvd.stop();
        dvd.off();
        amp.off();
        projector.off();
        lights.on();
        System.out.println("--- Home Theater Power Down Complete ---");
    }
}

// Demo Client
public class HomeTheaterDemo {
    public static void main(String[] args) {
        Amplifier amp = new Amplifier();
        Projector projector = new Projector();
        SmartLights lights = new SmartLights();
        DvdPlayer dvd = new DvdPlayer();

        HomeTheaterFacade homeTheater = new HomeTheaterFacade(amp, projector, lights, dvd);

        // Simple high-level method calls
        homeTheater.watchMovie("Inception");
        homeTheater.endMovie();
    }
}
```

```text

```

## 5. Summary & Key Takeaways

- **Simplified Access**: Provides a unified, high-level interface to complex multi-class subsystems.
- **Decoupling**: Shields client code from internal subsystem details and sequence changes.
- **Maintainability**: Internal subsystem workflow changes or new component additions do not break existing client code.
- **Subsystem Independence**: Subsystem classes remain accessible directly for advanced clients requiring low-level control.
