# Iterator Design Pattern

The **Iterator Design Pattern** is a behavioral design pattern that provides a standard mechanism to access elements of a collection sequentially without exposing its underlying internal structure.

![Iterator Design Pattern Overview](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.30-iterator-overview.png)

At its core, the Iterator pattern decouples the logic of traversing a collection from the collection data structure itself. Instead of allowing client code to access raw internal arrays, linked lists, or trees, the collection delegates traversal to a dedicated iterator object.

This pattern is particularly valuable when:
- You need to traverse complex collection structures (such as trees, lists, or graphs) in a uniform way.
- You want to support multiple distinct traversal strategies (e.g., forward, backward, filtered, or randomized).
- You want to encapsulate internal collection mechanics so client code remains decoupled from data representation changes.

Below is a detailed walk-through of how to apply the Iterator Pattern to build a maintainable, extensible, and standardized traversal architecture.

---

## 1. The Problem: Traversing a Playlist

Imagine building a music streaming application. Users create playlists, add tracks, and play songs in sequence. A playlist can hold hundreds of tracks, and the media player must step through them one by one.

A naive implementation might directly expose the internal data store:

```java
import java.util.ArrayList;
import java.util.List;

public class Song {
    private String title;
    private String artist;

    public Song(String title, String artist) {
        this.title = title;
        this.artist = artist;
    }

    public String getTitle() { return title; }
    public String getArtist() { return artist; }

    @Override
    public String toString() {
        return title + " - " + artist;
    }
}

public class Playlist {
    private List<Song> songs = new ArrayList<>();

    public void addSong(Song song) {
        songs.add(song);
    }

    public List<Song> getSongs() {
        return songs; // Exposing internal list directly
    }
}
```

```java
public class MusicPlayer {
    public void playPlaylist(Playlist playlist) {
        List<Song> songs = playlist.getSongs();
        for (Song song : songs) {
            System.out.println("Now playing: " + song);
        }
    }
}
```

### Why This Approach Fails at Scale

1. **Breaks Encapsulation**  
   Returning `List<Song>` allows external code to mutate internal collection state. Clients can accidentally clear, remove, or replace elements (`playlist.getSongs().clear()`).

2. **Tight Coupling**  
   `MusicPlayer` assumes `Playlist` uses a Java `List`. If you later switch the internal storage to an array, linked tree, or lazy database query stream, all client code breaks.

3. **Inflexible Traversal Logic**  
   To support playing songs in reverse order, shuffling, or skipping disliked tracks, the client must write custom loop structures. `Playlist` retains zero control over access strategies.

4. **Single Active Traversal Constraint**  
   If the collection tracks its own traversal pointer internally, simultaneous iterations by multiple threads or callers interfere with each other.

### Desired Architecture
We require a solution that:
- Hides internal collection representations from consumers.
- Exposes a unified traversal interface regardless of underlying data structures.
- Allows multiple concurrent, independent traversals.
- Supports varied traversal strategies (reverse, shuffle, filtered) without editing client code.

This is precisely what the **Iterator Pattern** achieves.

---

## 2. The Iterator Design Pattern

The Iterator Pattern encapsulates traversal state inside a separate iterator object. The collection delegates iteration duties while maintaining private storage.

Two key principles define the pattern:
1. **Separation of Traversal from Storage**: Data structure management resides in the collection; sequence movement resides in the iterator.
2. **Multiple Independent Iterations**: Every call to `createIterator()` returns a fresh iterator with its own cursor pointer, enabling concurrent traversals.

### Real-World Analogy

Consider a television remote control. When pressing the "Channel Up" or "Next" button, you don't need to know how the television indexes cable frequencies or satellite feeds internally. The remote provides a simple traversal interface (`hasNext()`, `next()`), hiding internal tuning complexities behind the remote buttons.

### Class Diagram

![Iterator Class Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.30-iterator-class-diagram.png)

### Pattern Participants

1. **Iterator (`Iterator<T>`)**  
   Defines traversal operations (`hasNext()`, `next()`).

2. **ConcreteIterator (`PlaylistIterator`)**  
   Implements `Iterator<T>`, tracking current cursor position over the target collection.

3. **IterableCollection (`IterableCollection<T>`)**  
   Declares the factory method (`createIterator()`) for instantiating iterators.

4. **ConcreteCollection (`Playlist`)**  
   Implements `IterableCollection<T>`, storing elements and returning matching concrete iterators.

---

## 3. How It Works

The workflow execution of the Iterator pattern follows these steps:

![Iterator Execution Workflow](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.30-iterator-workflow.png)

1. **Request Iterator**: The client invokes `playlist.createIterator()`.
2. **Instantiate Cursor**: The collection creates a `PlaylistIterator` instance, passing a reference to itself.
3. **Loop Execution**: The client loops using `iterator.hasNext()` and retrieves elements via `iterator.next()`.
4. **Completion**: When `hasNext()` returns `false`, traversal terminates cleanly.

## 4. Implementing the Iterator Pattern

Let's refactor the playlist system using the Iterator pattern.

### Step 1: Define the Iterator Interface

```java
public interface Iterator<T> {
    boolean hasNext();
    T next();
}
```

### Step 2: Define the Iterable Collection Interface

```java
public interface IterableCollection<T> {
    Iterator<T> createIterator();
}
```

### Step 3: Implement Concrete Collection (`Playlist`)

`Playlist` encapsulates `List<Song>`, exposing only index-based read access needed by iterators.

```java
import java.util.ArrayList;
import java.util.List;

public class Playlist implements IterableCollection<Song> {
    private final List<Song> songs = new ArrayList<>();

    public void addSong(Song song) {
        songs.add(song);
    }

    public Song getSongAt(int index) {
        return songs.get(index);
    }

    public int getSize() {
        return songs.size();
    }

    @Override
    public Iterator<Song> createIterator() {
        return new PlaylistIterator(this);
    }
}
```

### Step 4: Implement Concrete Iterator (`PlaylistIterator`)

```java
public class PlaylistIterator implements Iterator<Song> {
    private final Playlist playlist;
    private int index = 0;

    public PlaylistIterator(Playlist playlist) {
        this.playlist = playlist;
    }

    @Override
    public boolean hasNext() {
        return index < playlist.getSize();
    }

    @Override
    public Song next() {
        if (!hasNext()) {
            throw new java.util.NoSuchElementException("End of playlist reached.");
        }
        Song song = playlist.getSongAt(index);
        index++;
        return song;
    }
}
```

### Step 5: Client Execution & Verification

```java
public class IteratorPatternDemo {
    public static void main(String[] args) {
        Playlist playlist = new Playlist();
        playlist.addSong(new Song("Shape of You", "Ed Sheeran"));
        playlist.addSong(new Song("Blinding Lights", "The Weeknd"));
        playlist.addSong(new Song("Levitating", "Dua Lipa"));

        Iterator<Song> iterator = playlist.createIterator();

        System.out.println("Sequential Playlist Traversal:");
        while (iterator.hasNext()) {
            Song song = iterator.next();
            System.out.println("Playing: " + song);
        }
    }
}
```

### Console Output
```text
Sequential Playlist Traversal:
Playing: Shape of You - Ed Sheeran
Playing: Blinding Lights - The Weeknd
Playing: Levitating - Dua Lipa
```

### Key Benefits Achieved
- **Encapsulation Preserved**: Internal storage cannot be mutated directly by clients.
- **Implementation Decoupled**: Switching `Playlist` internal storage from `List` to an array or database requires zero client edits.
- **Concurrent Traversal**: Multiple independent iterators can traverse the same playlist simultaneously.

## 5. Extending the Design: Additional Traversal Strategies

To support reverse playback or shuffled execution, we instantiate specialized iterator classes without altering `Playlist` or client loop contracts.

### 1. Reverse Playlist Iterator

```java
public class ReversePlaylistIterator implements Iterator<Song> {
    private final Playlist playlist;
    private int index;

    public ReversePlaylistIterator(Playlist playlist) {
        this.playlist = playlist;
        this.index = playlist.getSize() - 1;
    }

    @Override
    public boolean hasNext() {
        return index >= 0;
    }

    @Override
    public Song next() {
        if (!hasNext()) {
            throw new java.util.NoSuchElementException("Reached beginning of playlist.");
        }
        Song song = playlist.getSongAt(index);
        index--;
        return song;
    }
}
```

### 2. Shuffle Playlist Iterator

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class ShufflePlaylistIterator implements Iterator<Song> {
    private final List<Song> shuffledSongs;
    private int index = 0;

    public ShufflePlaylistIterator(Playlist playlist) {
        this.shuffledSongs = new ArrayList<>();
        for (int i = 0; i < playlist.getSize(); i++) {
            shuffledSongs.add(playlist.getSongAt(i));
        }
        Collections.shuffle(shuffledSongs);
    }

    @Override
    public boolean hasNext() {
        return index < shuffledSongs.size();
    }

    @Override
    public Song next() {
        if (!hasNext()) {
            throw new java.util.NoSuchElementException("End of shuffled playlist reached.");
        }
        return shuffledSongs.get(index++);
    }
}
```

## 6. Practical Example: Notification System

Consider a notification center storing email, SMS, and push notifications. We provide iterators to traverse all items, filter by type, or process unread messages.

![Notification System Iterator Diagram](https://raw.githubusercontent.com/shouvik126/LLD_images/main/7.30-notification-iterator-diagram.png)

### Implementation

```java
import java.util.ArrayList;
import java.util.List;

// Model
public class Notification {
    public enum Type { EMAIL, SMS, PUSH }

    private final String message;
    private final Type type;
    private final boolean read;

    public Notification(String message, Type type, boolean read) {
        this.message = message;
        this.type = type;
        this.read = read;
    }

    public String getMessage() { return message; }
    public Type getType() { return type; }
    public boolean isRead() { return read; }

    @Override
    public String toString() {
        return "[" + type + "] " + message + " (Read: " + read + ")";
    }
}

// Collection
public class NotificationCenter {
    private final List<Notification> notifications = new ArrayList<>();

    public void addNotification(Notification n) {
        notifications.add(n);
    }

    public int getSize() { return notifications.size(); }
    public Notification getAt(int index) { return notifications.get(index); }

    public Iterator<Notification> createAllIterator() {
        return new AllNotificationsIterator(this);
    }

    public Iterator<Notification> createFilteredIterator(Notification.Type type) {
        return new FilteredNotificationIterator(this, type);
    }

    public Iterator<Notification> createUnreadIterator() {
        return new UnreadNotificationIterator(this);
    }
}

// Concrete Iterators
public class AllNotificationsIterator implements Iterator<Notification> {
    private final NotificationCenter center;
    private int index = 0;

    public AllNotificationsIterator(NotificationCenter center) {
        this.center = center;
    }

    @Override
    public boolean hasNext() { return index < center.getSize(); }

    @Override
    public Notification next() { return center.getAt(index++); }
}

public class FilteredNotificationIterator implements Iterator<Notification> {
    private final NotificationCenter center;
    private final Notification.Type targetType;
    private int index = 0;

    public FilteredNotificationIterator(NotificationCenter center, Notification.Type targetType) {
        this.center = center;
        this.targetType = targetType;
        advanceToNextMatch();
    }

    private void advanceToNextMatch() {
        while (index < center.getSize() && center.getAt(index).getType() != targetType) {
            index++;
        }
    }

    @Override
    public boolean hasNext() { return index < center.getSize(); }

    @Override
    public Notification next() {
        Notification n = center.getAt(index++);
        advanceToNextMatch();
        return n;
    }
}

public class UnreadNotificationIterator implements Iterator<Notification> {
    private final NotificationCenter center;
    private int index = 0;

    public UnreadNotificationIterator(NotificationCenter center) {
        this.center = center;
        advanceToNextMatch();
    }

    private void advanceToNextMatch() {
        while (index < center.getSize() && center.getAt(index).isRead()) {
            index++;
        }
    }

    @Override
    public boolean hasNext() { return index < center.getSize(); }

    @Override
    public Notification next() {
        Notification n = center.getAt(index++);
        advanceToNextMatch();
        return n;
    }
}
```

```java
// Client Demo
public class NotificationSystemDemo {
    public static void main(String[] args) {
        NotificationCenter center = new NotificationCenter();
        center.addNotification(new Notification("Welcome to the platform!", Notification.Type.EMAIL, true));
        center.addNotification(new Notification("Your OTP is 482910", Notification.Type.SMS, false));
        center.addNotification(new Notification("New comment on your post", Notification.Type.PUSH, false));
        center.addNotification(new Notification("Monthly invoice statement", Notification.Type.EMAIL, false));

        System.out.println("--- Unread Notifications ---");
        Iterator<Notification> unreadIterator = center.createUnreadIterator();
        while (unreadIterator.hasNext()) {
            System.out.println(unreadIterator.next());
        }

        System.out.println("\n--- Filtered EMAIL Notifications ---");
        Iterator<Notification> emailIterator = center.createFilteredIterator(Notification.Type.EMAIL);
        while (emailIterator.hasNext()) {
            System.out.println(emailIterator.next());
        }
    }
}
```

### Summary
The client consumption loop (`while (iterator.hasNext()) { iterator.next(); }`) remains identical across all iteration modes. Filtering and cursor advancing are completely encapsulated inside dedicated iterator strategies.
